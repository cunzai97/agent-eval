## 过滤闸（主人两轮裁定）

1. **可重复使用** —— 固定输入 + 快照 + 隐藏测试判分，可无限重跑、结果稳定。
2. **不依赖设备** —— 真机跑不稳的，用**确定性成本模型模拟**替代设备；模拟必须把原任务的决策内核完整保留（调度、预算、淘汰、接受率），只是把"显存/GPU"换成纸面参数。
3. **深度与广度** —— 与现有 50 题（calc 多故障定位、去重聚合、shell 小工具、记忆闭环）难度轴不重叠；新增题要拉开区分度，覆盖不同能力维度。

结果：原 18 题 → **17 题过**（12 道原生纯 CPU + 5 道模拟化设计），**1 道吸收**（G1 并入 G3），**0 道纯砍**。

## B. 模拟化通过（5 题，设备换成确定性成本模型，决策内核完整保留）

模拟原则：**把"显存/GPU"换成纸面参数**（容量、带宽、单价、接受率函数），原任务的调度/预算/淘汰/接受率决策一字不动，
判分全走精确数值核算。模拟面越小越好——只 mock 掉设备，不 mock 掉推理。

### B-1. sched-dualgpu-001 · 双卡流水线调度（原 G2）
- script-dev｜code_repo（纯 Python 调度器）｜来源 web-llama 08-01T01:03「V100 承担 prefill 的一部分，和 XTX 双卡流水线 prefill，XTX 单卡 decode」「Prefill 优先，Prefill 时不能 Decode」
- **模拟面** 两张卡的 prefill/decode 吞吐（token/s 常数表）、请求队列（prompt 长度序列）、三条调度规则：流水线切分 prefill、decode 只在 XTX、prefill 激活期间禁 decode。
- **任务** 实现调度器：给定设备参数矩阵 + 请求序列，输出逐时间片分配计划（哪张卡在跑哪条请求的哪个阶段、切分比例），最小化 makespan；附带每条请求的完成时刻核算。
- **隐藏测试** 不同吞吐矩阵（V100 快 prefill 慢 decode 的反转情形）、单条请求长于任一卡全速、全 prefill 批、全 decode 批、prefill 尾片与 decode 首片的边界交接不得重叠。
- **深度** 作业调度 + 约束满足（现有 50 题无调度题，这是系统思维轴的第一道）

### B-2. expert-placement-001 · MoE 三层专家放置与淘汰（原 G3，吸收 G1）

### B-3. spec-decode-001 · 双缓冲投机解码流水线（原 G4）
- script-dev｜code_repo（流水线模拟器）｜来源 web-llama 08-18「draft i+1 与 verify i 双缓冲并行」「双卡伪异步 MTP，主模型 prefill 完再单独 prefill MTP」
